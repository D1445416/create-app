# 產品需求文件 (PRD) - 台中大眾運輸交通整合APP系統

## 1. 專案概述
### 背景與動機
目前許多交通 APP 僅提供靜態的時刻表，缺乏即時且準確的到站資訊。對於大眾運輸的乘客而言，這常造成不必要的等候時間與行程延誤。本專案旨在開發一個整合台中地區大眾運輸的系統，提供精準的定位與即時的到站時間預估，幫助使用者更有效地規劃行程。

### 目標用戶
- 台中市民：日常通勤、就學、購物等頻繁使用大眾運輸的在地居民。
- 外地來的民眾：來台中旅遊、出差，對當地交通較不熟悉，需要可靠的轉乘與路線規劃指引的旅客。

### 核心價值主張
提供超越傳統時刻表的「精準到站時間」預估，整合多種大眾運輸工具（公車、捷運、台鐵、YouBike 等），透過精準定位與智慧路線規劃，為使用者節省等候時間並提供最適合的交通方案與成本評估。

## 2. 功能需求

### 主要功能清單與使用者故事

1. **時程準確性（即時到站預估）**
   - 作為 **通勤族**，我希望 **能看到公車或捷運精準的預估到站時間（而非僅表定時間）**，以便 **我能拿捏出門的時間，避免在站牌枯等。**

2. **大眾運輸工具檢視圖**
   - 作為 **外地遊客**，我希望 **能在地圖上直觀地看到附近所有可用的交通工具站點（捷運站、公車站牌、YouBike站）**，以便 **我能快速決定要搭乘哪種交通工具。**

3. **定位精準化**
   - 作為 **使用者**，我希望 **系統能精準定位我的當下位置**，以便 **自動為我推薦距離最近的上車點與路線，不用手動輸入起點。**

4. **規劃路線與替代方案**
   - 作為 **乘客**，我希望 **在輸入目的地後，系統能提供多種路線選擇及突發狀況下的替代方案**，以便 **我在遇到塞車或班次延誤時，能彈性切換其他交通方式。**

5. **價格推算**
   - 作為 **精打細算的市民或學生**，我希望 **在路線規劃時能一併看到每種方案的預估車資總計**，以便 **我能在時間與金錢成本之間做出最佳的選擇。**

6. **在台中地區規劃（在地化深度整合）**
   - 作為 **台中市民或外地遊客**，我希望 **系統深度整合台中市的交通路網與觀光景點資訊**，以便 **在市區內移動時能獲得最在地、最合理的轉乘建議。**

7. **到達目的地所需時間**
   - 作為 **趕時間的旅客**，我希望 **系統能精確計算包含步行、等車及乘車的總耗時**，以便 **我能準時赴約。**

## 3. 非功能需求

### 技術限制
- 後端框架：使用 Flask 進行 API 與邏輯開發。
- 模板引擎：使用 Jinja2 渲染前端頁面。
- 資料庫：使用 SQLite 作為關聯式資料庫，儲存用戶資料、搜尋歷史與基礎交通節點資訊。

### 效能與安全考量
- **效能**：介接即時交通數據的 API（如 TDX 平台）需有適當的快取（Cache）機制，避免過度頻繁請求導致延遲，確保路線規劃的回應時間在 3 秒內。
- **安全**：妥善保護使用者的位置資訊與搜尋紀錄，符合隱私規範；使用參數化查詢防止 SQL Injection 攻擊。

## 4. MVP 範圍 (Minimum Viable Product)

- **Must Have (必須有)**
  - 精準的定位功能。
  - 即時到站時間查詢（公車、捷運）。
  - 基本的路線規劃與到達目的地總時間估算。
- **Should Have (應該有)**
  - 大眾運輸工具檢視圖（地圖模式查看附近站點）。
  - 路線票價總計推算。
- **Nice to Have (可以有)**
  - 智慧替代方案（當前路線擁塞時的主動推播建議）。
  - 常用路線收藏與一鍵查詢。
