# 產品需求文件 (PRD) - 台中大眾運輸交通整合 APP

## 1. 專案概述
### 背景與動機
在日常生活中，搭乘大眾運輸工具時，轉乘接駁往往耗費大量時間。使用者難以準確掌握不同運具（如捷運轉公車）的到站時間與定位。本專案旨在透過整合即時數據，提供精準的定位與到站資訊，節省使用者等候時間，並優化行程規劃。

### 目標用戶
- 台中市民
- 來台中旅遊或出差，需要搭乘大眾運輸的民眾

### 核心價值主張
提供一站式的交通資訊平台，整合公車、捷運等即時動態，透過直觀的地圖介面與聯動面板，讓使用者在單一頁面即可掌握所有轉乘資訊。

## 2. 功能需求
| 功能編號 | 功能名稱 | 使用者故事 (User Story) |
| --- | --- | --- |
| F-01 | 一站式平台 | 作為使用者，我希望在一個平台就能查詢所有大眾運輸資訊，以便我不必切換多個 App。 |
| F-02 | 即時動態資訊 | 作為使用者，我希望看到公車與捷運的即時位置與到站時間，以便我準確安排出門時間。 |
| F-03 | 轉乘路徑演算 | 作為使用者，我希望系統能提供「捷運+公車」的最佳組合路徑，以便我最快抵達目的地。 |
| F-04 | 試算時間與價格 | 作為使用者，我希望知道不同路線的預計花費與時間，以便我選擇最符合預算的方案。 |
| F-05 | 常用路線收藏 | 作為使用者，我希望收藏常用的站點，以便我下次能快速查看資訊。 |
| F-06 | 多運具整合面板 | 作為使用者，我希望在地圖點擊站點時，側邊欄能同時顯示公車與捷運資訊，以便我快速比對轉乘時機。 |
| F-07 | 站點擁擠度 | 作為使用者，我希望知道車廂或站點是否擁擠，以便我選擇較舒適的班次。 |

## 3. 非功能需求
- **技術限制**：使用 Python Flask + Jinja2 + SQLite + Leaflet.js。
- **易用性**：介面需直觀，支援響應式設計（RWD）。
- **準確度**：即時數據需定期更新，並顯示數據更新時間。

## 4. MVP 範圍
- **Must Have**: 即時動態資訊 (F-02)、一站式平台 (F-01)、互動式地圖 (F-06)。
- **Should Have**: 轉乘路徑演算 (F-03)、常用收藏 (F-05)。
- **Nice to Have**: 站點擁擠度 (F-07)、時間價格試算 (F-04)。
