# 產品需求文件 (PRD)：台中大眾運輸站點狀態與擁擠度顯示系統

## 1. 專案概述
- **背景與動機**：民眾在尖峰時段搭乘大眾運輸時，經常面臨車廂或站點過度擁擠的困擾。若能提前掌握站點的人潮狀況，乘客即可選擇避開擁擠時段或改搭其他交通工具，提升搭乘體驗。
- **目標用戶**：台中市民，以及前往台中需要搭乘大眾運輸（捷運、公車）的民眾與遊客。
- **核心價值主張**：提供直觀、即時的站點與車廂擁擠度視覺化指標，幫助使用者做出更舒適的通勤決策。

## 2. 功能需求
1. **即時擁擠度顯示功能**
   - 作為 **通勤族**，我希望 **能在頁面上看到各站點的擁擠度顏色指標（紅：擁擠、橘：普通、綠：通暢）**，以便 **快速判斷目前站點的舒適度**。
2. **站點資訊查詢功能**
   - 作為 **一般使用者**，我希望 **能搜尋或點擊特定站點（如捷運站或公車站）**，以便 **查看該站詳細的人潮狀況與資訊**。
3. **TDX API 資料介接與更新**
   - 作為 **系統**，我希望 **能定期或即時從 TDX API 抓取捷運及公車的載客資料**，以便 **保持頁面上顯示的擁擠度資訊是最新的**。
4. **路線與擁擠度篩選功能**
   - 作為 **搭乘特定路線的乘客**，我希望 **能篩選特定捷運線或公車路線**，以便 **只關注我即將搭乘的路線狀況**。
5. **使用者位置周邊站點推薦**
   - 作為 **遊客**，我希望 **系統能根據我的定位，顯示距離我最近的幾個站點及其擁擠度**，以便 **我能快速決定要去哪個站點搭車**。

## 3. 非功能需求
- **技術限制**：
  - 後端：Python (Flask 框架)
  - 前端：HTML/CSS/JS (搭配 Jinja2 模板引擎)
  - 資料庫：SQLite (可用於儲存部分靜態站點資料或快取)
  - 外部資料源：交通部 TDX (Transport Data eXchange) API
- **效能考量**：
  - 由於依賴外部 API，系統應實作適當的資料快取機制 (Cache)，避免頻繁向 TDX 發送請求導致超出 Rate Limit，同時確保前端頁面載入速度。
- **安全考量**：
  - 妥善保管 TDX API 的介接金鑰 (Client ID / Client Secret)，不可外洩於前端程式碼中或直接上傳至公開的程式碼庫。

## 4. MVP 範圍 (Minimum Viable Product)
- **Must Have (必須有)**
  - 介接 TDX API 取得即時資料。
  - 將資料轉換為「紅、橘、綠」三色視覺指標。
  - 基本的站點列表與擁擠度呈現。
- **Should Have (應該有)**
  - 站點搜尋與特定路線篩選功能。
  - 響應式網頁設計 (RWD)，支援手機版瀏覽。
- **Nice to Have (可以有)**
  - 透過 GPS 定位顯示周邊站點。
  - 特殊事件（如跨年、燈會）的人潮警示推播。
