# 產品需求文件 (Product Requirements Document; PRD)

## 一、專案概述

### 1.1 背景與動機
在日常生活中，我們需要搭乘大眾運輸工具時，每次在連接，都會花費大量時間。例如，搭乘捷運要轉乘公車時，往往無法很準確地定位公車或該運輸工具的即時位置。因此，我們希望透過「台中大眾運輸交通整合APP」來整合各類大眾運輸資訊，節省使用者候車與轉乘的時間，並清晰呈現台中大眾運輸的動線，幫助市民與遊客更明確地規劃行程、緩解候車焦慮。

### 1.2 目標用戶
- **台中市民**：日常通勤、通學，需要頻繁在捷運、公車、YouBike 與火車之間轉乘的人群。
- **外地遊客**：來台中旅遊，需要透過大眾運輸工具前往各個景點（如逢甲大學、一中街、國家歌劇院等）的旅客。

### 1.3 核心價值主張
- **時程準確性**：提供高精準度的預估抵達時間（ETA），而非單純靜態時刻表。
- **跨運具一站式平台**：整合捷運、公車、YouBike、火車，免除切換多個 App 的麻煩。
- **最佳化轉乘路線**：提供時間最短或價格最低的轉乘搭配組合與地圖指引。

## 二、功能需求

本系統的七大核心功能如下，每項功能均以使用者故事（User Story）格式呈現，其中以 **F-03（多運具轉乘路徑演算）** 為本次開發的重點：

| 功能編號 | 功能名稱 | 使用者故事 |
| --- | --- | --- |
| **F-01** | 一站式平台 | 作為大眾運輸使用者，我希望在首頁輸入起迄點，以便快速查詢跨運具的整合轉乘路線。 |
| **F-02** | 即時動態資訊 | 作為公車或捷運乘客，我希望在地圖上看到車輛的即時定位與到站倒數，以便決定何時前往站點。 |
| **F-03** | **轉乘時間最佳化路徑演算** *(本模組)* | **作為需要多次轉乘的通勤族，我希望系統能自動結合「捷運 + 公車」、「火車 + YouBike」等組合，以演算法計算出最快抵達的路線，以便省下不必要的候車時間。** |
| **F-04** | 試算時間與價格功能 | 作為預算有限的學生或旅客，我希望在路線明細中看到預估總票價，以便比較並選擇最省錢的路線方案。 |
| **F-05** | 常用路線與轉乘點收藏 | 作為日常通勤族，我希望一鍵收藏常用路線，以便每天開啟 App 時能一秒查詢最新狀態。 |
| **F-06** | 多運具即時動態整合看板 | 作為在轉乘點等車的乘客，我希望在同一個地圖側邊面板同時看到公車進站與捷運班次，以便隨時調整我的交通選擇。 |
| **F-07** | 站點擁擠度顯示 | 作為注重乘車舒適度的乘客，我希望查閱站點與車廂的擁擠程度，以便避開人潮。 |

## 三、非功能需求

- **技術架構限制**：
  - 前端：HTML / CSS / JavaScript（純前端，無框架，地圖元件採用 Leaflet.js）。
  - 後端：Python 3 + Flask 輕量級 Web 框架。
  - 資料庫：SQLite，用以儲存常用收藏或歷史轉乘記錄。
- **品質要求**：
  - **準確度**：大眾運輸 GPS 即時動態定位（如 TDX API）需保證時效，地圖標記隨之更新。
  - **易用性**：起迄點選擇需具備防呆機制（例如：起點與終點不能相同、提供下拉選單以防拼寫錯誤），介面需為響應式（RWD）以便在手機上直觀操作。
  - **效能**：路徑規劃演算法（Dijkstra）執行時間需控制在 100ms 以內，避免使用者在前端等待過久。

## 四、MVP 範圍 (Minimum Viable Product)

為了確保專案能如期交付，功能依優先權劃分如下：

| 優先級 | 功能描述 | 對應模組 |
| --- | --- | --- |
| **Must Have (必須包含)** | - 基礎 Flask 專案架構建立<br>- **多運具轉乘 Dijkstra 演算法核心邏輯**<br>- **Leaflet.js 互動式地圖路徑折線繪製與標記**<br>- 起訖地標下拉選單與時間軸路線明細 | F-03 核心 |
| **Should Have (應該包含)** | - TDX API 即時動態數據串接與定時更新機制<br>- 票價與時間試算功能<br>- LocalStorage/資料庫儲存收藏記錄 | F-02, F-04, F-05 |
| **Nice to Have (非必要)** | - 站點擁擠度綠-黃-紅視覺化顯示<br>- 離線資料快取機制 | F-07 |
